# Hirify-бот — удалёнка и крипто-вакансии с прямыми Telegram-контактами

Telegram-бот на **aiogram 3.31** (Bot API 10.x), который:

1. следит за разделами [hirify.me](https://hirify.me/): **Удалёнка**, **Глобальная удалёнка**
   и **Crypto & Web3** (список разделов настраивается) с фильтром `only_direct_contact=1&contact_types=telegram`;
2. открывает каждую новую вакансию и ищет в ней **прямой Telegram-контакт рекрутера** (ссылки `t.me/…`, `tg://user?id=…`, `tg://resolve?domain=…`, упоминания `@username`);
3. дополнительно строго проверяет раздел: из «удалёнки» выкидывает офис/гибрид, из «крипты» — вакансии без крипто-признаков;
4. присылает вакансии **сразу, как только нашёл** — проверяет фид раз в **~25–40 минут** (плавающий ритм, `POLL_MINUTES=30`), ночью (01:00–07:00 МСК) — втрое реже, а после находки повторяет проверку уже через пару минут, так что «пачка» новых вакансий уходит подряд, без ожидания следующего цикла;
5. оформляет карточку **в стилистике Apple с панельной глубиной**: заголовок → компания и раздел → жирная зарплата → таблица-панель фактов → тонкий разделитель `<hr/>` → **полное описание, сворачиваемое прямо в карточке** (разворачивается одним касанием, без заглушек и ссылок на сайт) → выделенная панель рекрутера → мелкий футер с **относительной свежестью** («опубликовано сегодня/вчера/3 дня назад»; никаких упоминаний источника вакансий в карточке нет); три вида карточек на выбор (в `/settings`, при смене вида сразу приходит демо в новом виде):
   - 🫧 **Пузырь** — HTML-виджет (Bot API 10.4, Telegram 13.2+): настоящий CSS с тенями и панелями, кнопки прямо в карточке;
   - ✨ **Rich Messages** (Bot API 10.1+) с автоматическим откатом на классический `parse_mode=HTML`;
   - 📄 **Классика** — работает в любом клиенте (факты и контакт — панелями-цитатами `blockquote`);
6. даёт «прямой доступ» к рекрутеру: кнопка **«Написать рекрутеру»** открывает чат одним касанием (в классике — акцентная, Bot API 9.4 `style=primary`), плюс кнопка **«Копировать контакт»**; если у вакансии несколько Telegram-контактов — остальные уходят в сворачиваемый блок «Ещё Telegram-контакты». Лишних кнопок нет («Пост в канале» и «Вакансия на Hirify» убраны);
7. у каждого подписчика **свои настройки**: в `/settings` можно включать/выключать разделы, выбрать **вид карточек** (Пузырь / Rich / Классика / Авто) и включить тихий режим (без звука) — применяется мгновенно и хранится в БД.

## Как устроено

```
адаптивный цикл (обычно раз в 5 минут; после находки — повтор через 2 минуты)
 │
 ├─ для каждого раздела из HIRIFY_FEEDS — фид из JSON-API:
 │    GET api.hirify.me/api/vacancies?{фильтр раздела}&only_direct_contact=1
 │        &contact_types=telegram&sort_by=newest&page=N
 │    │   remote  → work_format=remote   (Удалёнка)
 │    │   global  → remote_type=global   (Глобальная удалёнка)
 │    │   crypto  → search=crypto        (Crypto & Web3)
 │    └─ сервер сам отдаёт только вакансии с прямыми TG-контактами
 │
 ├─ отбираем те, которых ещё нет в SQLite (дедупликация по всем разделам)
 │
 ├─ для каждой: авторизованный JSON-API api.hirify.me (Laravel Sanctum)
 │    ├─ GET  /api/vacancies/<slug> — должность, компания, зарплата, формат, теги,
 │    │   описание, AI-резюме (tldr)… — всё разом, надёжнее парсинга HTML
 │    ├─ POST /api/vacancies/<slug>/contacts — прямой контакт (t.me-юзернейм
 │    │   рекрутера или его пост в канале; сервисные боты hirify отфильтрованы)
 │    ├─ строгие фильтры: Remote/Hybrid/Onsite, крипто-признаки, скам-пометки
 │    └─ есть прямой контакт? → карточка уходит подписчикам СРАЗУ, не дожидаясь остальных
 │
 ├─ ретраи: сбой сети → повтор в следующем проходе (до 3 попыток); 404 — сразу «failed»;
 │    401/419 (сессия истекла) → подсказка админу и ретрай после оживления cookie;
 │    если Telegram не принял ни одну отправку — вакансия вернётся ретраем (send_failed)
 │
 └─ было новое в этом проходе? → следующий проход уже через FAST_POLL_SEC секунд
```

## Установка

Нужен **Python 3.10+**.

```bash
cd hirify-bot
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# впишите BOT_TOKEN (и при желании HIRIFY_COOKIE)
```

## Шаг 1. Токен бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте имя и username бота.
3. Скопируйте токен вида `123456:ABC-DEF...` в `.env` → `BOT_TOKEN`.

## Шаг 2. Сессия hirify.me (чтобы видеть контакты)

Без входа на сайт hirify прячет и контакты, и названия каналов-источников
(«Show contacts», «Name available after authorization»). Бот ходит на
`api.hirify.me` с cookie-сессией, как браузер (Laravel Sanctum: строка вида
`hirifyme_session=…; remember_web_…=…; XSRF-TOKEN=…`).

Два способа:

- **Автоматически (GitHub Actions)**: воркфлоу `auth` сам регистрирует аккаунт
  по email-OTP (временный ящик) и кладёт сессию в секреты `HIRIFY_COOKIE` +
  `HIRIFY_EMAIL`/`HIRIFY_PASSWORD` — повторный вход на сайте не нужен.
  Дальше сессию продлевает воркфлоу `refresh` (раз в месяц или вручную: кнопка
  «Run workflow»). Запуск `auth` при живой сессии не нужен.
- **Своей сессией**: войдите на [hirify.me](https://hirify.me), `F12` → Network →
  `F5` → первый запрос к `hirify.me` → **Request Headers** → `Cookie:` →
  **Copy value**. Затем:
  - либо `.env` → `HIRIFY_COOKIE=…` (или секрет `HIRIFY_COOKIE` в репозитории)
    и перезапуск бота;
  - либо прямо в чат: `/setcookie <строка>` (бот удалит сообщение с cookie;
    в режиме Actions — до ближайшего перезапуска, обновите и секрет).

Если бот начал присылать вакансии без контактов или писать «сессия не
работает» — обновите её (refresh-воркфлоу или шаги выше).

## Шаг 3. Запуск

Вариант А — напрямую:

```bash
python main.py
```

Вариант Б — Docker (база живёт в `./data`, перезапускается сам):

```bash
cp .env.example .env   # впишите BOT_TOKEN
docker compose up -d --build
docker compose logs -f hirify-bot
```

Откройте своего бота в Telegram, нажмите **Start** — бот пришлёт демо-карточку,
сразу проверит фид и начнёт следить за вакансиями. Проверить вручную: `/fresh`.

## Запуск на GitHub Actions (24/7, бесплатно)

Вариант В — без своего сервера: бот живёт в публичном репозитории и работает
через воркфлоу [`.github/workflows/bot.yml`](.github/workflows/bot.yml).

Как это устроено: job GitHub Actions живёт максимум **6 часов**, поэтому бот
через 330 минут (`RUN_MAX_MINUTES=330`) плавно останавливается, воркфлоу
**коммитит состояние в ветку** (SQLite: дедуп вакансий, подписчики, настройки)
и **запускает сам себя** (`workflow_dispatch` — единственный триггер, который
разрешено дёргать встроенным `GITHUB_TOKEN`, без циклов). Новый ран ждёт
окончания старого (`concurrency`) — эстафета продолжается. Зазор между ранами
~1–2 минуты: команды, присланные в него, не теряются
(`DROP_PENDING_UPDATES=0`). Страховка от обрыва эстафеты — `schedule` раз в 6 ч.

Настройка (один раз):

1. Репозиторий должен быть **публичным** — минуты Actions бесплатны и без лимита.
2. Секреты: **Settings → Secrets and variables → Actions**:
   - `BOT_TOKEN` — токен от @BotFather (обязательно);
   - `PAT_TOKEN` — тонкий PAT с правом `repo` (перезапуск ранов и запись секретов
     ботами `auth`/`refresh`);
   - `HIRIFY_COOKIE` + `HIRIFY_EMAIL`/`HIRIFY_PASSWORD` — сессия hirify.me.
     Проще всего создать их автоматически: **Actions → auth → Run workflow** —
     бот зарегистрирует аккаунт по email-OTP (временный ящик) и сам запишет
     все три секрета. Cookie хранится только в секретах: из коммитимой БД он
     вычищается автоматом. Если обновлять его через `/setcookie`, он действует
     до ближайшего перезапуска (бот предупредит) — для постоянного эффекта
     обновите секрет и перезапустите ран.
   - Воркфлоу `refresh` продлевает сессию раз в месяц (повторный вход по
     HIRIFY_EMAIL/HIRIFY_PASSWORD → свежий HIRIFY_COOKIE).
3. Запустить: **Actions → bot → Run workflow** (или просто запушить в `main` —
   пуш в основную ветку перезапускает бота с новым кодом). Остановить: **Actions →
   bot → … → Cancel** и отключить воркфлоу кнопкой `…` → **Disable workflow**.

Честные ограничения:

- перезапуск каждые ~5,5 ч с зазором 1–2 мин и запуском раннера ~1 мин (кэш pip
  помогает); «мгновенная доставка» всё равно мгновенная — внутри рана;
- никакого SLA: Actions — это CI-система, хостинг сервисов — серая зона
  (тихие хобби-боты живут так годами, но правила это не поощряют);
- scheduled-воркфлоу отключается после 60 дней неактивности репозитория — но наши
  регулярные коммиты БД сами считаются активностью, так что это не про нас;
- состояние живёт в git: ~4 маленьких коммита БД в день (файл десятки КБ).

Когда бот обживётся — переехать на VPS/fly.io проще простого: `git clone` и
`python main.py` (или Docker), БД забирается из репозитория как есть.

## Ритм опроса — «суточный цикл человека»

Карточка приходит **как только найдена**:

- бот проверяет фид раз в **~25–40 минут** (`POLL_MINUTES=30`): интервал плавает (джиттер ×0.8–1.35) — «ровно каждые N минут, круглые сутки» — подпись бота, на которой сайты ловят автоматизацию;
- **ночью (01:00–07:00 МСК) интервалы ×3** (~75–120 мин) — как спящий человек: меньше всего ночных запросов как раз то, за что сайты чаще всего и флагают 24/7-ботов;
- **утренний проход «метлой»** — первый за день после ночи идёт глубже обычного (`CATCHUP_FEED_PAGES=4` стр. на раздел): ночной бэклог разбирается с запасом, и хвост не уходит со страницы 1 навсегда (та же логика, что после снятия паузы автоматизации);
- если в проходе было новое — повторная проверка уже через **~2 минуты** (`FAST_POLL_SEC=120`, тоже с джиттером, даже ночью — «хвост пачки» добираем сразу), так что «пачка» вакансий уходит подряд;
- каждая карточка отправляется в момент обработки вакансии, без батчей;
- `/start` и `/resume` запускают проверку немедленно, не дожидаясь интервала.

## Карточка из своего текста (`/card` и авто-детект)

`/card Senior Solidity Engineer | ChainX, 4-5k$ global remote, стек: EVM,
Foundry. Писать: @chainx_hr` — бот разбирает произвольный текст вакансии
(скопипащенный откуда угодно) и присылает карточку **во всех трёх видах**
(🫧 Пузырь, ✨ Rich, 📄 классика) — удобно сравнить и выбрать любимый в
`/settings`. То же самое бот делает **сам, без команды**: просто пришлите
текст вакансии сообщением или загрузите файл `.txt`/`.md` (до 512 КБ) —
детектор `looks_like_vacancy` проверяет, похоже ли сообщение на вакансию
(должность + зарплата + контакт + «удалёнка»/«опыт»/«обязанности» —
консервативно, порог в 3 «маяка»; соискателя «ищу работу…» и случайный
разговор бот распознавать не станет). Если вид не поддерживается в чате
(например, Пузырь нужен Telegram 13.2+), бот честно пишет, чем заменил.
Парсер (`app/textparse.py`) консервативен: что не уверен распознать — остаётся
в описании как есть. Зарплата понимает диапазоны, «от/до», k/к/тыс, валюты
($ USD USDT USDC ₽ RUB EUR UAH) и периоды (/мес, /час, /нед); контакты —
@упоминания, t.me-ссылки, `tg://user?id=`; грейд — Junior…Principal и
кириллицей. Ошибка парсинга исключена: в худшем случае карточка придёт с
заголовком из первой строки и полным описанием. В БД мониторинга (`jobs`)
ручная карточка не попадает — это разовый рендер.

## Настройки подписчика (`/settings`)

В `/settings` каждый подписчик настраивает рассылку под себя — глобальный
`.env` трогать не нужно:

- **разделы** — тумблеры по каждому разделу из `HIRIFY_FEEDS`:
  нажали «Удалёнка» — она выключилась/включилась, применяется сразу;
- **вид карточек** — radio-выбор, как оформлять вакансии (см. ниже);
- **тихий режим** — карточки приходят без звука (`disable_notification`);
- **«Как по умолчанию»** — сброс разделов к `HIRIFY_FEEDS`.

Настройки хранятся в SQLite (таблица `subscribers`, колонки `feeds`/`silent`/`display`)
и переживают перезапуск. Если ни один раздел не выбран — вакансии этому
подписчику не отправляются (в `/fresh` видно строку «подписчиков этих разделов
не нашлось»). Проверить свой вид карточек — `/test`.

## Вид карточек: Пузырь / Rich / Классика / Авто

Каждый подписчик выбирает формат в `/settings`, а `/test` присылает демо
в выбранном виде. При сбоях бот сам откатывается на следующую ступень
(`bubble → rich → classic`), и после 3 неудач подряд отключает проблемную
до перезапуска — доставка не страдает.

| Вид | Технология | Что видит подписчик |
|---|---|---|
| 🫧 **Пузырь** | HTML-виджет, `sendWidget` (Bot API 10.4, Telegram **13.2+**) | Карточка с настоящими тенями, панелями и кнопками прямо в сообщении: «Написать рекрутеру» открывает чат, «Копировать контакт» копирует @юзернейм. Палитра подстраивается под тему чата. Виджеты работают только в личном чате с ботом и не пересылаются |
| ✨ **Rich** | `sendRichMessage` (Bot API 10.1+) | HTML-разметка: h3-заголовок, компактная таблица фактов, сворачиваемое описание, панель рекрутера, кнопки внутри сообщения |
| 📄 **Классика** | `sendMessage` + `parse_mode=HTML` | Обычный текст с blockquote-панелями и инлайн-кнопками — работает в любом, даже самом старом клиенте |
| 🤖 **Авто** | rich → классика | Поведение прежних версий: пытаемся rich, при сбое — классика |

Особенности «Пузыря» (по официальному гайду [Telegram Widgets](https://core.telegram.org/bots/widgets)):

- высота виджета авто и **не скроллится** (50–600 px) — описание даётся тизером,
  полный текст разворачивается в rich/классике прямо в их карточках
  (`<details>` / `<blockquote expandable>`);
- HTML ≤32 КБ и ≤4096 байт после zlib-9 — бот проверяет лимит до отправки
  и при переполнении сам ужимает описание;
- caption виджета (виден в уведомлениях, поиске и клиентах без поддержки
  виджетов): «Должность · Компания · Зарплата»;
- если у рекрутера скрытый контакт (`tg://user?id=…`), кнопок внутри виджета
  нет — вместо них под виджетом обычная инлайн-клавиатура.

Глобальный выключатель — `USE_WIDGET=0` в `.env`: тогда даже выбравшим
«Пузырь» шлём rich/классику.

## Разделы вакансий (`HIRIFY_FEEDS`)

Бот мониторит несколько разделов hirify.me сразу — это готовые лендинги сайта
с предустановленным серверным фильтром (быстро и без лишних запросов):

| Ключ | Раздел на hirify.me | Лендинг |
|---|---|---|
| `remote` | Удалёнка (полностью удалённые IT-вакансии) | [/remote-it-jobs](https://hirify.me/remote-it-jobs) |
| `global` | Глобальная удалёнка (work from anywhere) | [/remote-jobs](https://hirify.me/remote-jobs) |
| `crypto` | Crypto & Web3 (крипто-индустрия) | [/web3-crypto-jobs](https://hirify.me/web3-crypto-jobs) |
| `crypto_remote` | Crypto & Web3 только удалёнка | [/web3-crypto-remote-jobs](https://hirify.me/web3-crypto-remote-jobs) |
| `all` | общий фид без раздела | [/](https://hirify.me/) |

Настройка — в `.env`:

```
HIRIFY_FEEDS=remote,global,crypto        # по умолчанию: все три
```

Можно добавить и свой лендинг: `HIRIFY_FEEDS=remote,crypto,/fintech-jobs`.

### Строгая проверка разделов (страховка)

Серверный лендинг уже отфильтрован, но бот дополнительно проверяет страницу
каждой вакансии:

- `REMOTE_STRICT=1` (по умолчанию) — из разделов удалёнки выкидываются вакансии,
  у которых на странице ЯВНО указан офисный/гибридный формат (чип «Hybrid»/«Onsite»);
  вакансии без признаков не трогаем;
- `CRYPTO_STRICT=1` (по умолчанию) — из раздела crypto остаются только вакансии
  с крипто-признаками (blockchain, web3, solidity, криптовалюта, биржи типа
  Binance/OKX/Bybit, USDT и т.д. — заголовок, навыки, компания или описание);
- `INDUSTRY_STRICT=1` (по умолчанию) — рассылать только вакансии целевых индустрий:
  iGaming, gambling, betting, дейтинг, high-risk- и NDA-проекты, крипта и смежные
  (casino, sportsbook, букмекер, лотерея, fantasy sports и т.д. — полный список
  паттернов `INDUSTRY_RE` в `app/parsing.py`). Вакансии «обычных» компаний
  отсеиваются как `skipped_off_industry`.

Отсеянные вакансии видны в `/stats` как «Не прошло фильтр раздела».

### Анти-флаг: не палимся под автоматизацию

hirify помечает аккаунт меткой `automation_detected` (403) за машинное поведение —
обычно за пачки просмотров вакансий подряд. Ограничение аккаунтное (~24 ч),
обновление cookie не помогает. Бот защищён несколькими слоями:

- **Имперсонация Chrome** (`curl_cffi`) — настоящий TLS-отпечаток ClientHello и
  HTTP/2, как у браузера; httpx с «питоновским» TLS — верный способ выдать себя.
  Цель — `IMPERSONATE_TARGET` (по умолчанию `chrome`, свежая известная).
- **Анонимные фиды** — лента читается БЕЗ cookie: круглосуточный поллинг
  не привязан к аккаунту. Cookie тратится только на данные вакансий и контакты.
- **Префильтр фида** (`FEED_PREFILTER=1`, по умолчанию) — «мимо индустрии»
  видно уже по элементу фида (title+tldr+стек+скам-флаги): вакансию НЕ открываем.
  Показательный день: 14 открытий → 0 карточек (всё — мусор мимо индустрии);
  теперь те же вакансии не открываются вовсе. Выключить — `FEED_PREFILTER=0`.
- **Квоты аккаунта** — `AUTH_VIEWS_HOUR_MAX=12`, `AUTH_VIEWS_DAY_MAX=80`:
  потолок запросов от имени аккаунта (данные+контакты). Остаток пачки
  не теряется — подберётся следующим проходом.
- **Человеческий темп** — лента листается шустро (`FETCH_DELAY_SEC`),
  вакансия «читается» `VACANCY_GAP_SEC=6,14` с, контакты открываются
  через `CONTACTS_GAP_SEC=4,9` с. Ровный метроном — подпись бота.
- **Память эскалации** — счётчик флагов держится 48 ч с последнего срабатывания:
  «сняли флаг и тут же снова флажим» не даёт паузе скатываться к минимуму в 90 мин.

Сервер отдаёт `X-RateLimit-Limit=60` (окно ~минута) — запас кратный даже
при «метле» из 4 страниц на раздел.

## Диагностика: `tools/dump.py`

Если что-то не парсится, проверьте, что именно видит бот (запускать там, где
hirify.me доступен):

```bash
python tools/dump.py feed              # первый раздел из HIRIFY_FEEDS
python tools/dump.py feed remote       # раздел «Удалёнка»
python tools/dump.py feed crypto       # раздел «Crypto & Web3»
python tools/dump.py feed global 2     # «Глобальная удалёнка», страница 2

python tools/dump.py demo          # самопроверка парсера на встроенном примере
```

Команда `job` печатает все извлечённые поля и найденные Telegram-контакты,
а исходный HTML сохраняет в `debug/job.html` — можно открыть глазами.

**Если hirify.me сменит вёрстку:** ссылки вакансий и TG-контакты ищутся
регекспами по сырому HTML, поэтому переживают смену CSS; основные данные — из
JSON-LD, который SEO-сайты почти всегда отдают. Сломаться может что-то
точечное (например, грейд) — карточка при этом останется рабочей.

## Частые вопросы

**Бот пишет «сессия не работает»** — cookie истёк. В режиме Actions: **Actions →
refresh → Run workflow** (повторный вход по HIRIFY_EMAIL/HIRIFY_PASSWORD).
Локально: повторите шаг 2. Аккаунт, созданный воркфлоу `auth`, можно
«оживить» и вручную — креды в секретах HIRIFY_EMAIL/HIRIFY_PASSWORD.

**В логах «сайт заподозрил автоматизацию» (403 automation_detected)** — сайт
иногда ставит временный флаг на серию запросов. Бот сам приостанавливает проход
и повторит в следующем цикле; помогите ему: не запускайте диагностические
воркфлоу подряд, `MAX_PER_POLL` держите умеренным (по умолчанию 8). Пауза
эскалируется с каждым повторным срабатыванием (90 → 240 → 480 → 960 → 1440 мин),
живёт в БД и переживает замещение ранов; на время паузы бот переворачивает фиды
реже (раз в 30 мин) и просыпается точно к её концу «метлой» — глубже обычного
(`CATCHUP_FEED_PAGES=4`), чтобы добрать всё накопленное без потерь. Джиттер
интервалов (×0.8–1.35) — часть той же защиты: метрономный ритм выдаёт бота.

**Никто чужой не должен управлять ботом** — задайте в .env/секрете
`ADMIN_CHAT_ID=<ваш chat_id>`: после этого `/setcookie`, `/pause` и `/resume`
принимаются только из вашего личного чата. Узнать свой chat_id можно у
@userinfobot. Без гарда (по умолчанию 0) команды доступны всем — приемлемо
только для строго личного бота.

**Rich-сообщения не приходят, только обычные** — Bot API 10.1+ доступен с серверной стороны
всем; если у вашего клиента/версии aiogram что-то не так, бот сам откатится на
классический HTML (см. логи: «Rich Message не прошёл…»). Выберите в `/settings`
другой вид — 📄 Классика.

**Выбрал «Пузырь», а приходит Rich/классика** — виджеты требуют **Telegram 13.2+**
у получателя и работают только в личном чате с ботом. Бот откатывается на
rich/классику после неудач (логи: «Виджет не прошёл…»). Проверьте версию
приложения и попробуйте /test; выключить виджеты совсем — `USE_WIDGET=0`.

**Ошибка 429 / медленно** — поднимите `POLL_MINUTES`, уменьшите `MAX_PER_POLL`,
увеличьте `FETCH_DELAY_SEC`. Бот и так делает паузы между запросами и между
отправками.

**«hirify.me временно ограничил просмотры вакансий»** — сайт пометил аккаунт
флагом автоматизации (403 `automation_detected`, ~24 ч, привязано к аккаунту,
не к сессии). Бот сам ждёт с эскалацией (90 → 240 → 480 → 960 → 1440 мин) и
добирает накопленное «метлой». Что можно сделать руками: ничего критичного —
просто подождать; профилактика описана в разделе «Анти-флаг» выше. Если флаги
стали регулярными — сузьте `HIRIFY_FEEDS` до целевых поисков
(`search=igaming` и т.п.), мусорных открытий станет меньше на порядок.

**Новые вакансии не приходят, а их мало?** — hirify обновляет источники каждые ~2 часа;
проверьте `/status` (не на паузе ли мониторинг) и `/fresh`.

**Юридическая оговорка.** Бот обращается к hirify.me как аутентифицированный
пользователь с вашей cookie и аккуратными паузами. Ответственность за
соответствие условиям использования сайта — на вас; не выставляйте агрессивные
интервалы опроса.

## Что нового в этой итерации

- **Вид карточек на выбор (в `/settings`)**: 🫧 Пузырь — HTML-виджет
  (Bot API 10.4, Telegram 13.2+): настоящий CSS — тени, панели, кнопки прямо
  в карточке (`openTelegramLink` / `copyText`), палитра из темы чата;
  ✨ Rich; 📄 Классика; 🤖 Авто (как раньше). `/test` присылает демо в
  выбранном виде; **смена вида в `/settings` сразу присылает демо-карточку
  в новом виде** — переключили «Пузырь» и тут же видите пузырь, без ожидания
  новой вакансии. Цепочка фолбэка `bubble → rich → classic` с отключением
  проблемного уровня после 3 подряд неудач; `USE_WIDGET` — глобальный
  выключатель. Выбор хранится в БД (колонка `display`, миграция автоматом).
- **Карточка**: тонкий разделитель `<hr/>` после фактов, мелкий футер `<footer>`
  с относительной свежестью («опубликовано сегодня/вчера/N дней назад», без
  упоминания источника), **полное описание — целиком в сворачиваемом блоке**
  (rich: до 32768 символов html — `<details>`; классика: автобюджет под
  4096 видимых символов — `<blockquote expandable>`), главная кнопка в
  классике — акцентного цвета (`style=primary`, Bot API 9.4). Дата из
  таблицы фактов убрана — там только факты о работе. Каждая доставка
  логируется с видом (`доставлено видом bubble/rich/classic`), откат
  виджета — WARNING с причиной.
- **`/settings`** — персональные разделы и тихий режим на подписчика
  (inline-тумблеры, применяется мгновенно, хранится в БД).
- **Надёжность**: потолок ретраев доставки (10 → статус `failed`, раньше —
  бесконечно); после 3 подряд неудач Rich-сообщений бот до перезапуска шлёт
  классику, не тратя попытки; исправлена потеря фоновых задач
  (`create_task` без сильной ссылки может собрать GC); при старте бота
  залежавшиеся апдейты сбрасываются (`drop_pending_updates`).
- **Деплой**: Dockerfile + docker-compose (база в volume), CI с pytest,
  `requirements-dev.txt`.
